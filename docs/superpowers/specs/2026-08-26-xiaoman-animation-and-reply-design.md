# 小满动画与 Codex 回复修复设计

**日期：** 2026-08-26  
**状态：** 已由用户选择方案 B 并授权直接实施

## 目标

让小满的动作播放稳定达到 30Hz，并提供 60Hz 可选模式；为舔嘴、眨眼、挠头三个待机动作补充约 30 个真实帧，修复动作素材的粉红/红色边缘污染；同时让桌面伴侣在跳转或不打开 Codex 前端的情况下，可靠地向可继续的 Codex 任务发送消息。

## 约束与现状

- 不修改 `~/.codex/pets/xiaoman/pet.json` 或原生 `spritesheet.webp`。
- 桌面伴侣继续使用自己的 host-only 资源，关闭桌面伴侣后原生 Codex 行为不受影响。
- 现有待机动作图集是 `8` 帧/动作，播放端通过 `setInterval` 改变 CSS 背景位置。
- 现有 Codex 服务优先尝试 app-server control socket；socket 不存在时退回本地 JSONL 扫描。运行中的任务走 `codex queue`，空闲任务走 `codex exec resume`。
- 本机实际验证表明两个 CLI 入口都可用；失败主要来自状态元数据与日志状态不一致，或恢复时传入已经不存在的工作目录。

## 方案

### 1. 资源与图像管线

为三个 host-only 待机动作各生成一组 10×3 的动作帧布局，最终每个动作得到 30 个 `192×208` 单元。最终图集使用 10 列、9 行：每个动作占连续三行，避免超宽纹理，同时保持背景定位计算简单。

视觉生成以已批准的原生小满正面帧和现有动作参考为 identity reference，通过私有 relay ImageGen 路径生成。生成结果先落入 `work/`，只在人工视觉检查通过后进入确定性构建流程。确定性流程负责：

1. 按布局检测并提取 30 个单元。
2. 去除绿色 chroma key，并清理透明像素下的隐藏 RGB。
3. 对贴近轮廓的低 alpha 粉红/红色污染做边缘局部去溢色；不改变舌头等轮廓内的自然颜色。
4. 统一基线、缩放和透明边距。
5. 输出 WebP 图集、接触表和逐帧 JSON QA 报告。

报告必须包含每帧可见像素、透明边界污染计数、色彩空间/清理算法标识；任一帧为空、出现内部透明断层或残留明显 chroma 污染时不得进入 `public/pet/`。

原生标准动作行仍保留原图，以免破坏 Codex 原生效果；它们会使用新的统一播放时钟。方案 B 的真实扩帧重点覆盖伴侣自己新增的三个待机动作，所有状态切换则统一采用新的时钟和端点衔接策略。

### 2. 播放与切换

`PetSprite` 改用 `requestAnimationFrame` 驱动的时间累加器，而不是独立 `setInterval`。动画刷新设置为 30 或 60，默认 30；每次只在逻辑帧确实变化时更新 React 状态，避免 60Hz 下无意义的重复渲染。

动作规格携带图集列数、基础行和帧数，不能再假定所有动作都是 8 列。动作切换时保留当前动作的最后有效帧直到下一动作首帧准备好，并要求新生成动作的首尾帧回到接近中立姿态；不叠加两个宠物层做 cross-fade，避免重影、粉边和颜色混合。拖动奔跑、悬停跳跃、状态动作和待机动作共用同一时钟与取消/完成机制。

### 3. Codex 回复链路

保持“原生能力优先、CLI 兼容回退”的边界：

- 运行中或等待中的任务：使用参数数组调用 `codex queue --thread ... --message ...`，不拼 shell 字符串。
- 空闲或错误任务：使用 `codex exec resume --skip-git-repo-check <id> - --json`，消息走 stdin，并要求收到 `turn.started` 后才向 UI 报告已启动。
- 读取会话时，活动状态以最新生命周期日志为准；app-server 的 `canAcceptDirectInput: false` 不能覆盖明确的 `active/waiting` 日志状态。只有授权等待才禁用直接回复。
- 恢复时只传入存在且为目录的 `cwd`；失效目录不应让整个 spawn 失败，服务应允许 Codex 以默认工作目录按 session id 恢复。
- 所有 transport 错误保留受限的 stderr/stdout 摘要，并映射为用户可理解的提示；发送失败时不清空输入、不伪造成功状态，成功后刷新任务列表。

不启用 remote-control，不直接写入 Codex JSONL，不替用户修改 Codex daemon 配置。

## 测试与验收

### 自动化

- 新增播放时钟/图集定位测试：30Hz 与 60Hz 的时间推进、30 帧动作行定位、动作切换不会选到透明尾帧。
- 新增色差构建报告断言：所有帧有前景，透明边界污染为零或低于明确阈值，透明像素隐藏 RGB 为零。
- 新增回复回归测试：日志判定的 active 任务即使 app-server 元数据不可直接输入仍可排队；失效 cwd 不会阻止 resume；resume 只有收到 `turn.started` 才报告成功；原始错误摘要可见。
- 运行全量 Vitest、三个 TypeScript 项目检查和生产构建。

### 实际 QA

- 在白色、深色和棋盘背景分别查看新图集接触表，确认毛色不发红、边缘无粉色光晕、舌头颜色仍自然。
- 在 30Hz 和 60Hz 下连续采样动作至少 3 秒，确认无透明尾帧、跳回第一帧或明显重影。
- 用临时 Codex QA session 验证空闲恢复和运行中排队；记录真实任务状态从发送到完成的变化。
- 从最终打包 `.app` 重启后重复一次发送验证，并更新发布目录与校验和。

## 非目标

- 本次不重绘或替换原生 Codex 宠物资源。
- 本次不实现 remote-control 配对、审批自动化或读取 Codex 回复正文。
- 本次不把所有原生 8 帧标准行重新交给图像模型重绘；优先保护原生效果，把扩帧资源投入用户明确指出卡顿的新增待机动作。
